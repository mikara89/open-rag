
## Optional graph storage

Later, relationships may be stored in:

```text
Neo4j

PostgreSQL recursive relationship model
```

For MVP, prefer relational graph tables first.

## pgvector strategy

Start simple:

```text
Exact vector search for small MVP datasets
Tenant/document metadata filters in every query
Add HNSW or IVFFlat index when volume grows
```

Important:

```text
Do not forget TenantId filter.
Do not mix embeddings generated by incompatible models.
Do not hardcode vector dimensions without tying them to the embedding model.
```

## Object key convention

Recommended:

```text
tenants/{tenantId}/documents/{documentId}/versions/{versionId}/original/{safeFileName}
tenants/{tenantId}/documents/{documentId}/versions/{versionId}/docling/document.md
tenants/{tenantId}/documents/{documentId}/versions/{versionId}/docling/document.json
tenants/{tenantId}/documents/{documentId}/versions/{versionId}/images/{imageId}.{ext}
tenants/{tenantId}/documents/{documentId}/versions/{versionId}/tables/{tableId}.json
```

## File storage abstraction

Prefer a rich result instead of returning only object key.

```csharp
public sealed record StoredObjectResult(
    string Bucket,
    string ObjectKey,
    string ContentType,
    long SizeBytes,
    string? ETag,
    string? Sha256
);
```

```csharp
public interface IFileStorage
{
    Task<StoredObjectResult> SaveAsync(
        Stream content,
        string objectKey,
        string contentType,
        CancellationToken cancellationToken = default);

    Task<Stream> OpenReadAsync(
        string objectKey,
        CancellationToken cancellationToken = default);

    Task DeleteAsync(
        string objectKey,
        CancellationToken cancellationToken = default);
}
```
